# Fan Loop (t4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy the deterministic fan loop on t4: it follows GPU load with the iDRAC fan offset, records everything, serves the endpoint Hermes will use, and sends urgent alerts to Telegram.

**Architecture:** A standard-library-only Python 3.10 package, `fanloop`, run by systemd as the dedicated user `fanloop`. Pure decision logic (busy detection, control rule, threshold policy, marks, holds, review watchdog) is kept apart from I/O (commands with timeouts, SQLite, the Telegram queue, HTTP) and is unit-tested with explicit time. `fanctl` talks to the loop over a local Unix socket; Hermes will use HTTP with a write token.

**Tech Stack:** Python 3.10 standard library (`sqlite3`, `http.server`, `urllib`, `subprocess`, `unittest`), systemd (`Type=notify` with a watchdog), sudoers, Ansible (`~/ansible`), rsync and rrsync to `docks`.

**Spec:** `docs/superpowers/specs/2026-11-12-gpu-fan-controller-design.md`

**Scope:** plan 1 of 2. It covers everything on t4 and `docks`: spec section 5, the loop's side of sections 7 and 8, and the live test. Plan 2, the Hermes side on `hag`, comes after this plan's live test. It covers spec section 6: analysis scripts, review cron jobs, Hermes's Telegram, the `hag` part of the playbook, checking Hermes cron's before/after commands, and the "Hermes" tests in section 8.

## Global Constraints

- **Python 3.10 compatible:** t4 runs 3.10.12; the laptop runs 3.11. Don't use `tomllib`, `ExceptionGroup`/`except*`, `typing.Self`, `datetime.UTC` or `enum.StrEnum`.
- **Standard library only**, at runtime and in tests (`unittest`). Nothing is installed with pip, on t4 or on the laptop.
- **Tests run from the repo root:** `python3 -m unittest discover -s tests -v`. Before deploying, they also run on t4 under its Python 3.10 (Task 16).
- **The repo is public:**
  - No IP addresses, admin account names, tokens or chat IDs in tracked files.
  - Before every commit, `git grep -nE '\b10\.[0-9]+\.[0-9]+\.[0-9]+\b|v[g]hiur|[0-9]{8,}:[A-Za-z0-9_-]{30,}'` must print nothing. The `[g]` keeps the pattern from matching its own text in this file.
  - Real values go in `.env` on the laptop or in the Ansible vault. `~/ansible` isn't a repo.
- **Git:** work on the branch `fan-loop`, not `main`. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Time is a parameter.** No logic module reads the clock itself.
  - `Controller` and `BusyDetector` take monotonic seconds.
  - Everything that's stored takes Unix wall-clock seconds: samples, events, episodes, versions, marks, holds, the watchdog and alert rate limits.
- **Nothing may block the control loop.** Every external command goes through `CommandRunner` with a timeout, and every Telegram message through `Alerter`'s background queue.
- **Root only for these 9 command lines**, each run as `/usr/bin/sudo -n <line>` (spec 5.10):
  ```
  /usr/bin/racadm get system.thermalsettings.FanSpeedOffset
  /usr/bin/racadm set system.thermalsettings.FanSpeedOffset 255
  /usr/bin/racadm set system.thermalsettings.FanSpeedOffset 0
  /usr/bin/racadm set system.thermalsettings.FanSpeedOffset 2
  /usr/bin/racadm set system.thermalsettings.FanSpeedOffset 1
  /usr/bin/racadm set system.thermalsettings.FanSpeedOffset 3
  /usr/bin/ipmitool sdr type temperature
  /usr/bin/ipmitool sdr type fan
  /usr/bin/ipmitool dcmi power reading
  ```
- **Values from the spec:**
  - **Levels:** Off < Low < Medium < High < Max. racadm codes: Off `255`, Low `0`, Medium `2`, High `1`, Max `3`.
  - **Starting thresholds:** Low 55°C, Medium 65°C, High 78°C; margin 5°C; hold time 180 s.
  - **Emergency:** at least 80°C on either card, or any SW/HW thermal slowdown → Max.
  - **Hard limits:** step-ups 45–78°C, rising, at least 3°C apart; margin 3–10°C; hold time 60–900 s; ambient inlet 15–40°C.
  - **Busy:** 45 W or 50% on either card for 10 s; ends after 60 s below on both.
  - **Only card 1 readable:** add 4°C.
  - **Timing:** poll every 5 s; marks time out after 900 s; watchdog after 13 h, then a reminder every 24 h.
  - **Write limits:** 2 `review` writes and 6 `user-chat` writes per 24 h.
  - **Evidence gate:** 3 episodes of at least 360 s.
  - **Holds:** at most 24 h ahead, or until cancelled.
  - **Retention:** raw samples for 30 days.
  - **Alerts:** rate limit of 1800 s per kind.
- **On t4, ask the user before stopping services or loading the GPUs**; a VoiceProfile lab test may be running. Tasks 16 and 18 have explicit stop-and-ask steps.

## Review Focus

1. **One card's `nvidia-smi` line is broken** (`[Unknown Error]`, or `[N/A]` in a field). Only that card is dropped and the other one still controls; nothing raises. Test in Task 5.
2. **racadm prints an error but exits 0, or prints text nobody expected.** A set only counts once the read-back shows the new level. Test in Task 5.
3. **Malformed or hostile HTTP requests:** bad JSON, wrong types, an oversized body, unknown fields, a missing or wrong token. The answer is 4xx, nothing changes, and the server keeps answering. Test in Task 12.
4. **A restart in the middle of things:** at Max after an emergency, with a hold active, a mark open or a watchdog incident open. The loop restores its state from storage and racadm, not from assumptions. Tests in Tasks 9, 10 and 13.
5. **Telegram unreachable for hours.** The queue stays bounded, drops the oldest messages and counts them, and the control rule carries on. Test in Task 11.

### Task 4: The control rule

**Files:** Create `fanloop/control.py`, `tests/test_control.py`. Modify `fanloop/replay.py` (add `run_control`).

**Interfaces:**
- Consumes: `Level`, `Thresholds`, `EMERGENCY_C`, `CardReading`, `BusyDetector`, `read_fan_test_csv`
- Produces:
  - `ControlConfig(single_card1_offset_c=4.0, blind_idle_power_w=238.0, blind_power_above_w=50.0, blind_hold_s=30.0)`
  - `ControlInputs(now: float, cards: Sequence[CardReading], busy: bool, inlet_c: float | None, system_power_w: float | None, hold_min: Level | None)`
  - `Decision(level: Level, reason: str)`. `reason` is one of `"emergency"`, `"step-up"`, `"floor"`, `"step-down"`, `"blind-load"`, `"blind-hold"` or `"steady"`.
  - `Controller(thresholds: Thresholds, cfg: ControlConfig)`, with:
    - the attribute `thresholds`, which can be replaced;
    - `decide(inp: ControlInputs, current: Level) -> Decision`;
    - `@staticmethod hotter_c(cards, offset_c: float) -> float | None`
  - `replay.run_control(rows, thresholds) -> list[tuple[float, Level, str]]`: level changes only. It starts at `OFF`, uses `BusyDetector` for busy, `inlet_c=None` and `hold_min=None`, and applies each decision as the new current level.

The order of rules matters and the tests don't fix it, so `decide` works in this order:
1. **Hotter card:**
   - both cards readable → the maximum;
   - only card 1 → its temperature + 4°C;
   - only card 0 → its temperature;
   - neither → **blind**, rule 3.
2. **Emergency:** if hotter ≥ `EMERGENCY_C`, or any card has `sw_thermal` or `hw_thermal`, the answer is `MAX` (`"emergency"`). Reset the step-down timer and leave blind state.
3. **Blind:**
   - On entering blind, remember `held = current`.
   - Load means `system_power_w >= blind_idle_power_w + blind_power_above_w` without a break for at least `blind_hold_s`.
   - With load: `max(held, MEDIUM, ambient_min if busy)` (`"blind-load"`). Otherwise: `held` (`"blind-hold"`).
   - Leaving blind clears this state.
4. **Floor** = `max(up, ambient_min(inlet) if busy else OFF, hold_min or OFF)`. `up` is the highest of LOW, MEDIUM and HIGH whose step-up temperature is ≤ hotter, else `OFF`.
5. **Floor above current:** the answer is the floor, `"step-up"` if `up` is the floor, otherwise `"floor"`. Reset the step-down timer.
6. **Current above floor:** a step-down threshold applies:
   - at `MAX`: `EMERGENCY_C − margin`, even while busy;
   - otherwise, when not busy: `step_up(current) − margin`;
   - otherwise, when busy: none at `LOW`, else `step_up(current − 1) − margin`.

   While hotter < threshold without a break for `hold_s` → `current − 1` (`"step-down"`), and the timer resets after each step. Any other case → `current` (`"steady"`), and the timer resets whenever the condition fails.
7. **Current equals floor:** the answer is `"steady"`, with the timer reset.

### Task 13: Config and the daemon loop

**Files:** Create `fanloop/config.py`, `fanloop/daemon.py`, `deploy/config.example.json`, `tests/test_daemon.py`

**Interfaces:**
- Consumes: all of the above
- Produces:
  - `Config`, a dataclass with these defaults:
    - **Paths and network:** `db_path="/var/lib/fan-controller/fan.db"`, `listen_host="0.0.0.0"`, `listen_port=8780`, `socket_path="/run/fan-controller/ctl.sock"`, `socket_group="fanctl"`, `secrets_dir="/etc/fan-controller/secrets"`
    - **Timing:** `dry_run=True`, `poll_s=5.0`, `ipmi_every_s=30.0`, `offset_read_every_s=60.0`, `watchdog_every_s=60.0`, `prune_every_s=3600.0`
    - **Command timeouts:** `nvidia_timeout_s=10.0`, `ipmi_timeout_s=15.0`, `racadm_timeout_s=20.0`
    - **Blind rule:** `blind_idle_power_w=238.0`, `blind_power_above_w=50.0`, `blind_hold_s=30.0`
    - **Failure handling and health:** `nvidia_fail_polls=3`, `llama_health_url="http://127.0.0.1:8080/health"`
    - **Backup:** `backup_target=""`, `backup_key="/etc/fan-controller/secrets/docks_ed25519"`, `backup_known_hosts="/etc/fan-controller/known_hosts"`, `backup_dir="/var/lib/fan-controller/backup"`
  - `load_config(path) -> Config` (JSON; unknown keys raise `ValueError`)
  - `Secrets(telegram_token, telegram_chat_id, write_token)` and `load_secrets(dir) -> Secrets`, reading the files `telegram_token`, `telegram_chat_id` and `write_token`, stripped
  - `sd_notify(msg: str) -> None`: a datagram to `$NOTIFY_SOCKET`, with a leading `@` meaning the abstract namespace. Does nothing if the variable isn't set.
  - `Loop(cfg, service, store, sensors, offset, controller, busy, tracker, alerter, marks, holds, watchdog, mono: Callable[[], float], wall: Callable[[], float], llama: Callable[[], bool | None])`, with `startup() -> None`, `step() -> None` and `run_forever(stop: threading.Event) -> None`
  - `main(argv) -> int`, run as `python3 -m fanloop.daemon --config PATH`

**`startup()`:**
- calls `store.current()`, which seeds v1, and `watchdog.ensure_started(wall)`;
- reads the offset: `current_level` is what it reads, or `None` if the read fails, in which case the first step always sets one;
- sends `alerter.alert("restart", "Fan loop started: offset {X}, dry-run {on|off}, thresholds v{n}")`.

**`step()`**, in this order. Each part is wrapped so that one exception logs the event `loop-error` and the step goes on:
1. **GPU readings:** `sensors.gpus()`. If the cards are incomplete or there's an error for `nvidia_fail_polls` polls in a row → `open_incident("nvidia", …)`. Both cards back → `close_incident`.
2. **IPMI:** every `ipmi_every_s`, or `power()` on every poll while no card can be read.
3. **Busy:** `busy.update(mono, cards)`.
4. **Hold and thresholds:** `holds.expire(wall)`; a hold that has just expired → `notify("Hold ended (end time reached)")`. Then `holds.current(wall)`, and `controller.thresholds = service.thresholds()[1]`.
5. **Decision:** `controller.decide(...)`.
6. **Acting on it.**

   **If the decision differs from `current_level`, or the last set failed:**
   - log the event `level` (`from`, `to`, `reason`);
   - a reason of `"emergency"` → `open_incident("emergency")`;
   - then `offset.set(level)`:
     - **ok:** `current_level = level`, `close_incident("racadm")`;
     - **failed:** `open_incident("racadm")`, keep the target, and retry on the next step.

   **Otherwise, every `offset_read_every_s`** (not in dry-run): `offset.read()`. A level that differs from `current_level` → the event `manual-change`, `alert("manual-change")`, and `current_level = read level`.
7. **Slowdown:** any SW/HW thermal flag → `open_incident("slowdown")`. 300 s without one → close it.
8. **Max not enough:** at `MAX` for at least 120 s, with hotter now at least 2°C above hotter 120 s ago → `open_incident("max-not-enough")`. Leaving `MAX` → close it.
9. **Episodes:** `tracker.update(...)`. A finished episode goes to `store.add_episode`.
10. **Sample:** `store.add_sample(...)`.
11. **Marks, watchdog, reminders:** `marks.expire(wall)`. Every `watchdog_every_s`: each message from `watchdog.check(wall, llama())` → `notify`, since the watchdog does its own once-per-incident and daily timing and the 30-minute limit mustn't swallow it. `holds.reminder(wall)` → `notify`.
12. **Pruning:** every `prune_every_s`, `store.prune(wall)`.
13. **Status:** `service.publish(snapshot)`, where the snapshot holds the cards, IPMI values, level, busy, `blind` and health: last poll age, and nvidia, ipmi and racadm ok.

**`run_forever`** runs at a fixed rate of `poll_s`, and calls `sd_notify("WATCHDOG=1")` after each step.

**`main`** loads the config and secrets, builds everything, calls `startup()`, starts the API, calls `sd_notify("READY=1")`, then `run_forever`.
